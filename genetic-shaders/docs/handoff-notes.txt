## Handoff notes: Genetic Shaders

### Architecture
- **Browser-only app:** Vanilla ES modules, Three.js, Vite, and plain CSS; Three.js and Vite are the only declared dependencies. <ref_snippet file="C:\WORK\genetic-shaders\AGENTS.md" lines="3-5" /><ref_snippet file="C:\WORK\genetic-shaders\package.json" lines="7-17" />
- **Schema-driven genotype:** `parameterSchema.js` defines gene types, bounds, defaults, groups, and UI hints. `Genotype` normalizes values and enforces constraints; shader uniforms and exported GLSL connect those values to rendering. <ref_snippet file="C:\WORK\genetic-shaders\src\config\parameterSchema.js" lines="14-20" /><ref_snippet file="C:\WORK\genetic-shaders\src\ga\Genotype.js" lines="4-8" /><ref_snippet file="C:\WORK\genetic-shaders\AGENTS.md" lines="18-29" />
- **Rendering split by workload:** One shared WebGL renderer serves the explorer grid through a frame-budgeted queue; a separate renderer handles the interactive 2D/3D hero preview. <ref_snippet file="C:\WORK\genetic-shaders\src\renderer\OffscreenTileRenderer.js" lines="17-20" /><ref_snippet file="C:\WORK\genetic-shaders\src\renderer\OffscreenTileRenderer.js" lines="60-100" /><ref_snippet file="C:\WORK\genetic-shaders\src\renderer\HeroPreviewRenderer.js" lines="9-12" />
- **Target matching and evolution:** Target images become cropped luminance fields and extracted features. The scorer combines histogram, spectral, curvature, and slope similarities; the scheduler evaluates an internal candidate pool and displays top candidates on the grid. <ref_snippet file="C:\WORK\genetic-shaders\src\matcher\ImageAnalyzer.js" lines="3-6" /><ref_snippet file="C:\WORK\genetic-shaders\src\matcher\FitnessEvaluator.js" lines="3-11" /><ref_snippet file="C:\WORK\genetic-shaders\src\ga\EvolutionScheduler.js" lines="19-30" />
- **State and UI:** A small pub/sub store owns app state and undo/redo; `main.js` wires it to the UI, renderers, matcher, and persistence helpers. <ref_snippet file="C:\WORK\genetic-shaders\src\state\store.js" lines="5-8" /><ref_snippet file="C:\WORK\genetic-shaders\src\main.js" lines="44-48" />

### Important decisions
- **Share WebGL contexts rather than creating one per tile.** Tiles render in a time-budgeted queue, with a timeout watchdog because animation frames can be throttled in background tabs. <ref_snippet file="C:\WORK\genetic-shaders\src\renderer\OffscreenTileRenderer.js" lines="17-20" /><ref_snippet file="C:\WORK\genetic-shaders\src\renderer\OffscreenTileRenderer.js" lines="73-100" />
- **Treat the parameter schema as the source of truth,** and funnel genotype creation through validation so mutations and loaded values obey bounds and guardrails. <ref_snippet file="C:\WORK\genetic-shaders\src\ga\Genotype.js" lines="25-41" /><ref_snippet file="C:\WORK\genetic-shaders\src\ga\Genotype.js" lines="50-70" />
- **Score images by multiple structural properties, not pixels alone.** Luminance is center-cropped to avoid distorting the FFT spectrum, and the fitness score includes a roughness/detail guard. <ref_snippet file="C:\WORK\genetic-shaders\src\matcher\ImageAnalyzer.js" lines="3-6" /><ref_snippet file="C:\WORK\genetic-shaders\src\matcher\FitnessEvaluator.js" lines="108-126" />
- **Keep evolution running when possible in hidden tabs** by scheduling with `setTimeout`; limit work per tick to keep the UI responsive. <ref_snippet file="C:\WORK\genetic-shaders\src\ga\EvolutionScheduler.js" lines="19-20" /><ref_snippet file="C:\WORK\genetic-shaders\src\ga\EvolutionScheduler.js" lines="417-440" />
- **Preserve reproducible artifacts at the genotype/session level:** genotypes and search sessions have serialized forms, and checkpoints use browser storage. The mutation/evolution process itself uses `Math.random`, so runs are not currently deterministic from a saved session. <ref_snippet file="C:\WORK\genetic-shaders\src\ga\Genotype.js" lines="14-22" /><ref_snippet file="C:\WORK\genetic-shaders\src\state\searchStorage.js" lines="6-31" /><ref_snippet file="C:\WORK\genetic-shaders\src\ga\EvolutionScheduler.js" lines="223-225" />

### Unresolved questions for the next agent
- **How reliable is matching quality across varied targets?** The score weights and thresholds are hand-calibrated in code; there is no visible test suite or benchmark protocol to establish expected scores or compare changes. Should a fixed target corpus and regression metrics be added? <ref_snippet file="C:\WORK\genetic-shaders\src\matcher\FitnessEvaluator.js" lines="86-106" /><ref_snippet file="C:\WORK\genetic-shaders\AGENTS.md" lines="86-92" />
- **What performance targets and minimum devices should be supported?** Rendering and candidate evaluation use bounded batches, but the documented checks focus on manual behavior rather than frame time, memory, or device/browser coverage. <ref_snippet file="C:\WORK\genetic-shaders\src\renderer\OffscreenTileRenderer.js" lines="8-9" /><ref_snippet file="C:\WORK\genetic-shaders\src\ga\EvolutionScheduler.js" lines="19-20" />
- **Should saved data have stronger migration guarantees?** Genotypes and search files carry version fields, but the shown deserialize/import paths do not branch on those versions. Define compatibility expectations before changing the schema. <ref_snippet file="C:\WORK\genetic-shaders\src\ga\Genotype.js" lines="14-22" /><ref_snippet file="C:\WORK\genetic-shaders\src\state\searchStorage.js" lines="1-2" /><ref_snippet file="C:\WORK\genetic-shaders\src\state\searchStorage.js" lines="82-94" />
- **Is deterministic evolution important?** Sessions preserve the current candidate state, but not an RNG state; decide whether exact run replay is a requirement or whether saving the best/current genotypes is sufficient. <ref_snippet file="C:\WORK\genetic-shaders\src\state\searchStorage.js" lines="25-31" /><ref_snippet file="C:\WORK\genetic-shaders\src\ga\EvolutionScheduler.js" lines="223-225" />
